## 4. 2a の利用者向け契約

| 入力 | 動作 |
|---|---|
| `claude-container <dir>` | 従来どおり Claude、選択記憶を読まない・書かない |
| `claude-container --agent codex <dir>` | 現行の Codex 経路、選択記憶を読まない・書かない |
| `c3c claude [<dir>]` / `c3c codex [<dir>]` | 明示した CLI。dir 省略時は現在のディレクトリ |
| `c3c [<dir>]` | 記憶があれば使用。なければ対話選択 |
| `c3c --agent codex [<dir>]` | 既存オプションの別表記を許容。サブコマンドとの重複は同値でも exit 2 |
| `c3c --read-only [<dir>]` | 最終選択が Codex の場合だけ有効。Claude なら exit 2 |
| `c3c --check [<dir>...]` | 選択待ちをしない・記憶を更新しない。無指定は既存の台帳全件診断、agent 無指定は現行どおり Claude |
| `c3c --agent codex --check <dir>` | 既存の Codex 診断。記憶による選択はしない |
| `c3c --clean [<dir>]` / `--check --clean-missing` | 既存の清掃範囲。選択・記憶の更新なし、agent 指定は拒否 |

`c3c` では最初の位置引数の `claude` / `codex` だけをサブコマンドにする。同名のディレクトリは `./codex` や `-- codex` と書く。`--` 以降はすべて位置引数で、通常起動の dir は最大1件。未知オプションは exit 2。旧入口の解釈をこの厳格化で変えない。

初回選択は `/dev/tty` から `1`（Claude）か `2`（Codex）を1回読み、不正値・EOF は exit 2、SIGINT は exit 130 で終了する。端末が無い場合は待たず exit 2 とし、明示指定の例を出す。stdin を消費しない。記憶を採用した場合は `INFO: 前回の選択: codex` のように採用した CLI を表示する。保存済みの CLI がガードで利用不能なら既存の理由に加えて明示再選択のコマンドを出して終了する。自動 fallback や失敗後の連続プロンプトは設けない。

サブコマンドも agent 明示指定として扱う。`c3c codex --check <dir>` は Codex 診断、`c3c claude --clean <dir>` は exit 2。`--read-only` 自体から agent を推定せず、初回選択・記憶・明示指定で決まった値を検証する。

### 記憶の形式と更新

新規の `agent-preference.py` は Git 識別・JSON の検証・原子的保存を担当する。秘密を読まない。launcher からのみ呼び、プロジェクト `env` で保存先や値を変更させない。

```text
agent-preference.py key <directory>                 # stdout に sha256 のキー
agent-preference.py read <state-directory> <key>     # stdout に claude/codex
agent-preference.py write <state-directory> <key> <agent>
```

識別文字列は Git の場合 `git\0<realpath(common-dir)>`、非 Git は `path\0<realpath(directory)>`。UTF-8 はファイルシステムの surrogateescape と対応させる。SHA256 全64桁を使う。別 clone は別、linked worktree と symlink 別名、同じ repo 内のサブディレクトリは共通。repo を移動すると新規の記憶になり再選択する。旧記憶の探索・移し替えは行わない。既存 image/承認のパス識別は変更しない。

Git 子プロセスには継承した `GIT_*` をすべて落とし、system/global 設定を無効にする値だけを設定して対象ディレクトリから解決する。Git 不在・非 Git は path 単位。対象 directory から祖先へ `.git` の有無を確認し、存在するのに解決できないケースは診断不能として記憶を使わない。明示 CLI なら WARNING 付きで起動し記憶を省略、無指定なら明示指定を求めて停止する。`--path-format=absolute` 非対応の Git も同じ診断不能扱い。Python 3 不在も明示 CLI は記憶省略、無指定は明示指定を案内して exit 2 とする。既存の Codex 経路が Python を必要とする制約は別途維持する。

保存先はホストの `$HOME/.local/state/claude-container/agent-preferences/<key>.json`。内容は `{"schema":1,"agent":"codex"}` のように2キー限定、重複キー・未知値・bool の schema・余分な内容・過大ファイル（4096 byte超）は拒否する。directory 0700、file 0600。symlink や非通常ファイルは読込・書込とも拒否する。書込は同じ directory に mkstemp、flush/close、os.replace、失敗時は自分の一時ファイルのみ除去する。

key の終了コードは 0=キー出力、4=診断不能。read の終了コードは 0=有効、3=未作成、4=破損または診断不能。未作成は初回選択へ、破損は WARNING の後に初回選択へ進む。write は 0=保存、1=失敗。明示 CLI は不正記憶の値を採用せず選択を優先する。

更新時点は **本起動の compose run が終了コード0で戻った後** とする。これは「最後に正常終了した CLI」の記憶であり、起動直後のクラッシュを記憶しない。preflight・build・承認拒否・中断・CLI の非ゼロ終了では旧値を保持する。保存失敗は WARNING とし、launcher の終了コードは常に本 run の終了コードを保持する。同時セッションは最後に正常終了した書込が勝ち、JSON が部分書込にならないことを保証する。clean 系では記憶を削除しない（image/承認の清掃とは寿命が異なる）。

## 5. 2b の契約

### 2b-1: 設定名だけの移行

起動 checkout の直下に対して次の表を適用する。入口名によって設定探索結果を変えない。

| `.c3c` | `.claude-container.d` | 通常起動 / check |
|---|---|---|
| なし | なし | `.c3c` を参照元として既存 fallback。directory は作らない |
| directory | なし | `.c3c` を採用 |
| なし | directory | 旧名を採用し移行推奨 WARNING。check は既存 WARN 集計へ |
| 存在 | 存在 | 内容が同じ・同じ実体でも ERROR、混ぜない |
| file / dangling link 等 | なし（または逆） | ERROR、ビルドや env 読込より前に停止 |

directory へ解決できる symlink は既存互換のため許容する。二重配置は `-e` だけでなく `-L` でも検出する。設定探索関数は結果を返してから `readonly PROJECT_CONF_DIR` を確定する。`--check` は対象ごとのサブシェルで診断し、1対象が不正でも次対象へ進む。check では `select_project_conf_dir || return 20` とし、失敗後に env・resolver・hash を呼ばない。期待出力は `[FAIL]` の原因と既存の FAIL 集計で、unexpected exit や unbound variable にしない。clean 系は設定選択エラーを理由に清掃を中止しないよう、設定解決を cleanup 分岐より後に置く。

移行ツールは追加せず、起動していない利用側で backup を設定探索の対象外へ置き、`mv .claude-container.d .c3c` を明示的に行う。追跡対象なら `git mv`、ローカル設定の `.gitignore` も利用側で更新する。env 内容をログへ出さない。`--check` 後に必要なら `-b`、両 CLI 起動を確認。元へ戻す際は `.c3c` を旧名に戻して旧 launcher を使う。両 directory を並べて backup にしない。

### 2b-2: 既定イメージ

新規の同梱 `node-version.txt` を `24.18.0\n`、`codex-version.txt` を `0.155.1\n` とする。Node は今回調査した既存利用設定と同値、Codex は現在の審査対応版と一致させ、latest へ追従させない。この版の組合せの実ビルド合格がマージ条件で、未実測の互換性を保証しない。

`resolve_asset_source()` のこの2項目を project 優先→同梱 default に変更する。project に空ファイルがあれば明示 opt-out として維持する。旧配置にも同じ fallback を適用する。`allowed-ports.txt`・`base-image.txt` の missing 契約は維持する。`stage_build_context()`・`compute_asset_hash()`・`guard_codex_agent()` は同じ resolver の結果を使う。

Codex 同梱は認証設定の自動作成を意味しない。CODEX_DIR は明示設定のまま、未設定なら Codex 起動を診断して停止する。既存の `latest` 指定への警告・未知版拒否は維持する。通常起動と `--check` の両方で Node/Codex の採用元（project/default/空によるopt-out）を表示する。Node opt-out＋Codex 有効では、base に npm があるかをホストから断定せず WARNING とし、npm が必要であることと Codex も空で無効化できることを build 前に案内する。通常起動は進行可能、check は WARN 集計へ入れる。旧イメージを自動削除せず、hash drift と `--check` でリビルドを案内する。
