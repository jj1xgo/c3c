# `~/.claude/dev-mods` を `:ro` の保護に足し、mod が壁を越えうることを書く Implementation Plan（#201）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude Code の mod（plugin の一種で、Claude Code のプロセスの中で動く）について、#201 の調査で分かった 2 点を c3c に反映する。1 つ目は、セッション中に Claude が書く mod の置き場 `~/.claude/dev-mods/` を `:ro` の保護に足して、この mount 経由ではコンテナの中からホストの `~/.claude` に mod を残せないようにすること。2 つ目は、mod が `permissions.deny` と PreToolUse hook を越えて承認しうることを、README のその 2 つを「壁」と書いている箇所に書き足すこと。

**Architecture:** 保護の一覧の正本 `CLAUDE_CONFIG_RO_DIRS`（`c3c`）に `dev-mods` を `.git` の前へ足し、`compose.yml` に 1 行のマウントを足す。作成・型の検査・`--check` の WARN は、今の `prepare_claude_config_ro()` の配列を回す仕組みがそのまま扱う。保護の合計は 12 項目から 13 項目になる。テストの一覧と期待値を合わせ、`dev-mods` に固有の確認を足す。文書は README・SECURITY-CLAIMS.md・`docs/development-invariants.md`・`docs/runtime-ci.md`。

**Tech Stack:** bash（`c3c`・`test-build.sh`）、Podman Compose、python3 の unittest。

**Spec:** Issue #201 の 2026-10-18 のコメント（一次資料の引用と URL）。持ち主の決定（2026-10-18）: 「13 項目目として `:ro` に足す」（コンテナの中で Claude に mod を書かせられなくなるのは受け入れ済み）。前例: `docs/superpowers/plans/2026-09-19-claude-git-ro-129.md`（`.git` を足した計画）。

## Global Constraints

- 区分は境界。`c3c`・`compose.yml` を変える前に `docs/development-invariants.md` の `~/.claude` の `:ro` 保護の箇条（`#129` の `.git` の箇条の周り）を読む。
- `dev-mods` は `CLAUDE_CONFIG_RO_DIRS` の `output-styles` と `.git` の間に入れる（`.git` を配列の末尾に残し、G 系のテストの「各配列の末尾」の前提を保つ）。`compose.yml` の行も同じ位置。
- `dev-mods` の注釈（`c3c` の一覧の前と `compose.yml` で同じ趣旨）: 「`dev-mods` はセッション中に Claude が書く mod の置き場（`~/.claude/dev-mods/<セッション ID>/`）。そのセッションが次に始まるときに読み込まれ、mod は Claude Code のプロセスの中で sandbox の外で動き、`permissions.deny` や PreToolUse hook を越えて承認しうるため、hook と同じ扱いにする（#201）。」
- 数の書き換えは「合計」だけにする。「12 項目」「12項目」（合計の意味）は 13 にする。序数の「12 項目目」（`docs/development-invariants.md` の `.git` の箇条）は数を直さず、序数を外す（Task 3 Step 5 の逐語）。済んだ計画 `docs/superpowers/plans/` は変えない。
- 挙動の変更と README の変更は同じ commit にする（root `AGENTS.md`「挙動を変えたら README.md の該当節も同じコミットで更新する」）。Task 1〜3 を 1 つの commit にする。
- `./lint.sh` は rc 0。Compose 検証はコンテナでは not run（podman が無い）なので CI で補う。
- 公開リポジトリなので、計画の写しにホストのパス・session id・個人運用の置き場を書かない。
- Expected と違う結果が出たら、その Step で止まり、出力を添えて持ち主に報告する（その場で原因を調べない）。

## Review Focus

1. ホストに `~/.claude/dev-mods` がすでに実ディレクトリとしてあり、中にファイルがあるとき: 起動は止まらず、中身は変わらず、コンテナから読めて書けない（Task 1 の `A3` と、実イメージの probe の読み取りの確認）。
2. ホストの `~/.claude/dev-mods` が symlink のとき: ERROR で止まり、何も作らない（Task 1 の `B3`）。
3. `dev-mods` だけが欠けているとき、`--check` が WARN し、何も作らない（Task 1 の `C3`）。
4. コンテナの中の Claude Code が mod を書こうとしても EROFS で失敗し、ほかの rw の場所へ書き直さない（Task 5 Step 1 の手動の確認）。
