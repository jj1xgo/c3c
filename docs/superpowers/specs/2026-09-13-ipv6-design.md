# IPv6 を任意で有効化する設計

対象: Issue #96、基準 `8787f1d`。ユーザー承認: 既定の IPv4 動作を維持し、任意の IPv6 と同等の許可リストを実装する。通常の実装判断はホスト側で進める。

## 利用者に見える動作

`.claude-container.d/env` の `CLAUDE_CONTAINER_IPV6=1` で IPv4/IPv6 を併用する。未指定・空・`0` は既存の IPv4 モード。その他は通常起動と `--check` で拒否する。設定変更はランタイムだが、初回は新しい境界アセットを含むイメージの `-b` が必要。対応ラベルのない旧イメージの再利用は起動と `--check` で拒否し、`-b` による再ビルドを案内する。

IPv6 有効時も `allowed-domains.txt` と `allowed-ports.txt` を共用し、許可先・許可ポート以外は拒否する。IPv6-only ホスト、ホスト/WARP 設定の自動変更、プロキシ導入は範囲外。既存の `CLAUDE_CONTAINER_NO_FIREWALL=1` は全ファイアウォールを無効化する既存の明示的設定として維持する。

## ネットワーク方式

既定の Compose は bridge を維持する。有効時だけ固定の `compose.ipv6.yml` を追加し、`network_mode: pasta:-g,fe80::1`、IPv6 sysctl の0、コンテナの IPv6 モード1を指定する。launcher が選んだファイルと mode を一致させ、環境文字列を任意のネットワーク引数として渡さない。

根拠: ホストは WARP の別ルーティングテーブルで IPv6 HTTPS 成功。rootless bridge は外側の名前空間に IPv6 既定経路がなく失敗。単独 pasta のゲートウェイ明示で成功した。実 Compose の keep-id・capability 剥奪・sudo 初期化・IPv4 許可/遮断も確認済み。provider が sysctls のリスト/マップ混在を拒否するため両ファイルをマップ形式にそろえる。

モード切り替え時は bridge を再利用しない。pasta はコンテナ単位に閉じ、終了時に消える。既存 bridge の自動削除はせず、既存の `--clean` が担当する。IPv4 のゲートウェイ例外は従来どおり検出したゲートウェイ1個とするが、pasta では物理側ゲートウェイであり、bridge と同じホストサービスへの別名ではない。Podman は既定で `--no-map-gw` を指定するため、gateway から host loopback への写像も無効になる。IPv6 ゲートウェイへの TCP 全許可は追加しない。

## 実装の分担

- launcher: 設定許可リスト、検査、固定 override 選択。`--check` は通信/ネットワーク作成を行わない。
- entrypoint: 検証済み0/1から `init-firewall.sh --ipv6` を選び、15秒更新にも同じ引数を渡す。sudo の環境変数保持に依存しない。
- init-firewall.sh: 既存のホスト名/ポート検証を利用し、IPv6 初期化、AAAA 更新、自己検証を専用スクリプトへ委譲する。既定の A レコード処理は維持。併用時のみ A の NOERROR/応答なしを正常として AAAA へ進む。
- ipv6-firewall.py: Python 標準ライブラリ `ipaddress` による正規化、実 ip6tables への引数配列による呼び出し、DNS/世代ルール管理。`python3` を固定依存として導入し、スクリプトは root 所有755。依存欠落は起動失敗とする。

専用スクリプトは `prepare`、`refresh`、`verify` を持つ。`prepare --ports ...` が静的ルールを初期化し、`refresh --ports ... --generation ...` が stdin の全ホスト名を検証して AAAA を解決・更新・削除する。`verify` が IPv6 に限定した通信検査を行う。追加アセットはステージングとドリフト検知の対象とする。

## IPv6 の境界

- INPUT/OUTPUT/FORWARD は DROP。loopback、確立済み/関連接続を許可する。
- IPv6 リゾルバへの TCP/UDP 53のみを許可する。IPv4 リゾルバは既存側で扱う。zone付きリゾルバは interface 指定に分解し、存在する interface のみ受理する。
- ICMPv6 の1〜4（到達不能・Packet Too Big・時間超過・パラメータ問題）を許可する。近隣探索135/136は hop limit 255、RS133は ff02::2宛て、RA134は fe80::/10 送信元かつ hop limit 255に限定する。
- 宛先許可は `2000::/3` の global unicast と `fc00::/7` の ULA に限る。未指定・loopback・IPv4-mapped・multicast・link-local等の AAAA は警告して除外する。ゾーンに依存する link-local 宛てサービスの追加許可は初期対応外。
- GitHub IPv6 CIDR も同じアドレス範囲内だけ受理し、許可ポートを適用する。
- IPv6 アドレスは `ipaddress` で正規化し、実 `ip6tables -S` の表記と意味で照合する。新世代を追加後、同じドメイン/IPの旧ルールを行番号降順に削除する。追加失敗時は旧ルールを残す。コメント上限255バイトは実際のタグ長で判定する。
- 約180秒見えなかったルールを削除する。AAAA の NOERROR/応答なしと NXDOMAIN は正常な不在、一時的失敗はエラー。初期化時のエラーは起動停止、定期更新時は警告して次の周期へ進む。失敗時も古いルールを永続化せず通常の猶予期間で削除する。
- IPv6 経路なし、IPv6無効、ip6tables利用不可、IPv6 HTTPS自己検証失敗は起動停止。自己検証は `api.anthropic.com` の443許可、同ホストの80拒否、`example.com` の443拒否を IPv6 限定で行う。

## 検証

既存227件の全体テストが基準。追加テストは設定と override 選択、entrypoint引数、アドレス正規化、AAAA 応答別の処理、世代の追加→削除/期限、カーネルコマンド失敗を実処理で検証する。外部境界（DNS・iptables）のみを fixture にする。CI は両 Compose 構成と新規 Python テストを含める。

実コンテナでは両モード、IPv6 許可/遮断、カウンタ、IPv4維持、設定異常による起動停止、世代更新、capability 剥奪、Compose 清掃を確認する。実ネットワークの長期間の CDN ローテーションは未実行なら明記する。実装後は Claude レビューを行い、Critical/Important解消後にPRを作る。
